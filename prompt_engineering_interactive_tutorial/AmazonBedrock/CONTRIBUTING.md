# 贡献指南

感谢您对本项目贡献的兴趣。无论是错误报告、新功能、修正还是补充文档，我们都非常重视来自社区的反馈和贡献。

在提交任何问题或拉取请求之前，请仔细阅读本文件，以确保我们有所有必要的信息来有效回复您的错误报告或贡献。


## 报告错误/功能请求

我们欢迎您使用 GitHub 问题跟踪器来报告错误或提出功能建议。

提交问题时，请检查现有的已打开或最近关闭的问题，确保没有其他人已经报告过该问题。请尝试包含尽可能多的信息。以下细节非常有用：

* 可重现的测试用例或一系列步骤
* 您正在使用的代码版本
* 您所做的与该错误相关的任何修改
* 关于您的环境或部署的任何异常情况


## 通过拉取请求贡献

非常感谢通过拉取请求做出的贡献。在向我们发送拉取请求之前，请确保：

1. 您正在 *main* 分支的最新源代码上工作。
2. 您检查了现有的已打开和最近合并的拉取请求，以确保没有人已经解决了该问题。
3. 您打开一个问题来讨论任何重要的工作 - 我们非常不希望您的时间被浪费。

要向我们发送拉取请求，请：

1. 派生（fork）该仓库。
2. 修改源代码；请专注于您正在贡献的特定更改。如果您也重新格式化了所有代码，我们将很难专注于您的更改。
3. 确保本地测试通过。
4. 使用清晰的提交信息提交到您的派生仓库。
5. 向我们发送拉取请求，回答拉取请求界面中的任何默认问题。
6. 关注拉取请求中报告的任何自动化 CI 失败，并参与讨论。

GitHub 提供了关于[派生仓库](https://help.github.com/articles/fork-a-repo/)和[创建拉取请求](https://help.github.com/articles/creating-a-pull-request/)的额外文档。


## 寻找可贡献的工作

查看现有问题是找到贡献目标的好方法。由于我们的项目默认使用标准的 GitHub 问题标签（enhancement/bug/duplicate/help wanted/invalid/question/wontfix），因此查看任何标记为"help wanted"的问题是一个很好的起点。

如果您发现本项目中存在潜在的安全问题，我们要求您通过我们的[漏洞报告页面](http://aws.amazon.com/security/vulnerability-reporting/)通知 AWS/Amazon Security。请**不要**创建公开的 GitHub 问题。
